# Rime / 万象拼音集成说明

## 一、目标与结论

| 要求 | 实现 |
| --- | --- |
| 集成 fcitx5-rime 插件 | 沿用仓库内已有的 `plugin/rime`（fcitx5-rime 1.12.0 + 预编译 librime） |
| 集成 rime-wanxiang 词库 | 新增 git submodule `plugin/rime/src/main/cpp/rime-wanxiang`（固定 commit），随 rime 插件的 `rime-data` 一起部署 |
| 作为默认中文方案来源 | `default.yaml` 的 `schema_list` 首位改为 `wanxiang`，`luna_pinyin*` 作为兜底 |
| 默认提供双拼 | 首次运行写入 `wanxiang.custom.yaml`，默认启用 **自然码** 双拼（`wanxiang_algebra:/base/自然码`） |
| 首次自动部署 | 输入法首次创建输入视图时自动写入用户配置；librime 自身在首次启动做 full check 编译词库 |
| 减少手工操作 | 全部配置文件由 App 生成，用户无需手动复制 YAML |

## 二、目录与数据流

```
plugin/rime/src/main/cpp/rime-wanxiang/     ← submodule（amzxyz/rime-wanxiang, CC-BY-4.0）
        │  CMake install()
        ▼
rime 插件 APK assets/usr/share/rime-data/   ← 与 luna_pinyin 数据同一棵树
        │  DataManager 首次部署（签名/版本校验后解包）
        ▼
<appData>/usr/share/rime-data/              ← librime shared_data_dir
        │  fcitx5-rime 启动
        ▼
<extData>/data/fcitx5/rime/                 ← librime user_data_dir
        default.custom.yaml                 ← App 生成：方案列表 + 默认方案 + 候选数
        wanxiang.custom.yaml                ← App 生成：双拼键位 + 模糊音
```

用户目录路径来自 `native-lib.cpp` 设置的 `XDG_DATA_HOME=<extData>/data`，与
`fcitx5-rime/src/rimeengine.cpp` 中 `StandardPaths::userDirectory(PkgData) / "rime"` 完全一致。

## 三、默认方案与配置

- **默认方案**：`wanxiang`（万象拼音，标准版）
- **默认双拼**：`自然码`
  - 可选：自然码、小鹤双拼、搜狗双拼、微软双拼、智能ABC、紫光双拼、国标双拼、拼音加加、全拼
  - 对应补丁：`wanxiang_algebra:/base/<方案名>`
- **候选数量**：默认 6
- **模糊音**：默认全部关闭，可在图形界面逐个开启（`wanxiang_algebra:/模糊音_*`）
- **兜底**：若检测不到 `wanxiang.schema.yaml`（例如用 `-DINCLUDE_WANXIANG_DICT=OFF` 构建），
  `schema_list` 中的 `luna_pinyin_simp` 仍可用，输入法不会不可用。

生成的文件带 `# Generated by fcitx5-android (xuexgao). Do not edit by hand;` 头，
避免用户与 App 双向覆盖；用户如需手改，应在界面上关闭对应项或使用"恢复默认"。

## 四、图形化配置（功能 → Rime 方案）

- **状态**：显示当前默认方案、万象拼音是否已部署
- **默认方案**：点击列表项即可切换
- **方案列表**：逐个开关启用/禁用（默认方案不可关闭）
- **双拼方案**：列表选择，右侧显示写入的 algebra 键名
- **参数**：候选数量、6 组模糊音
- **操作**：重新部署 / 导出配置 / 导入配置 / 恢复默认

所有改动即时写入 `*.custom.yaml`；"重新部署"通过 fcitx5-rime 的 `fcitx-rime-deploy`
动作触发，找不到该动作时退化为 `reloadConfig()`。

## 五、体积与开关

完整词库约 54 MB（`dicts/` 下 zi/jichu/cuoyin/duoyin/diming/mingren/yiren 为必需）。
如需精简构建：

```bash
./gradlew -PcmakeArgs="-DINCLUDE_WANXIANG_DICT=OFF" ...
```

或在 `plugin/rime/src/main/cpp/CMakeLists.txt` 中把 `INCLUDE_WANXIANG_DICT` 默认值改为 `OFF`。
此时只安装方案与 Lua 脚本，词库回落到内置 luna_pinyin。

## 七、"代替默认中文 26 键"的准确含义

要求 6 的这一句落地为两点，避免误解：

1. **26 键布局本来就是默认**：`TextKeyboard.A` 的 `getDefaultLayout()` 就是 QWERTY 26 键，
   本次没有改动键盘布局与输入逻辑。
2. **默认中文输入源改为万象拼音**：Rime 的 `schema_list` 首位为 `wanxiang`，用户配置里默认启用
   自然码双拼，因此启用 Rime 后默认就是"万象拼音 · 26 键 · 双拼"。

需要说明的边界：Rime 引擎来自独立的 `plugin/rime` APK（本仓库构建产物之一），
Android 不允许应用静默安装另一个 APK，因此**"默认"成立的前提是已安装 Rime 插件**。
未安装时：

- 主页"默认中文方案"仍会显示 `wanxiang`（这是期望配置），
- Rime 方案页会显示"未检测到，请确认已安装 Rime 插件"，
- 输入仍由内置拼音提供（同样是 26 键），不会出现输入法不可用。

## 八、已知限制

1. 首次部署需编译约 54 MB 词典，中低端机型可能耗时数十秒；期间输入法仍可切换到
   `luna_pinyin_simp` 使用。
2. 万象拼音的 `.lite` 精简词库不在上游仓库内（只有引用），因此未提供"精简词库"选项；
   如需按需下载应接入 `rime-wanxiang-data` 的 release。
3. 导出的配置文件是两份 YAML 的拼接（带 `#### 文件名` 分隔标记），便于人工查看，
   导入时按标记拆分回写。
